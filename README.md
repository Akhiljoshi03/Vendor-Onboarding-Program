# Project 3 — Vendor Onboarding Program
**Work streams demonstrated:** Product Operations, Program Management
**Focus area:** Supply Chain — Inbound (Procurement, Cataloging, Pricing & Promotions)

## What this is
An end-to-end operational artifact set for onboarding new vendors' product
catalogs — the kind of "make the team run efficiently" work the JD's
Product Ops and Program Management streams call out explicitly, as
distinct from the more analysis-heavy Projects 1 and 2.

## Why this project for this JD
The JD names both streams directly:
- **Product Operations:** "build and run SOPs so the product team operates
  efficiently... document releases and internal knowledge."
- **Program Management:** "coordinate across Engineering, Design and QA,
  track timelines and blockers."

This project shows both in a single connected scenario — a documented SOP,
a RACI that makes accountability explicit, a multi-vendor launch timeline
with a real blocker log (not a static Gantt chart), and a stakeholder
communication plan with an example update — rather than treating "process
work" as an afterthought to analytics.

## How to read this project
1. `SOP_vendor_onboarding.md` — the standard process, with SLAs and
   exception handling for one vendor.
2. `RACI_matrix.md` — who's accountable for each step, and why that
   prevents a specific common failure mode.
3. `launch_timeline.md` — scaling the SOP to 12 vendors onboarding in
   parallel, with the scheduling decisions that protect the SLA under load.
4. `stakeholder_comms_plan.md` — how progress and risk get communicated to
   six different stakeholder groups, including a sample update.
